## 🎭 **Ato 2 – Explicação (O Desenvolvimento)**

### 📚 **O que é uma Biblioteca JS? (React como exemplo)**

"React é uma **biblioteca** porque **você controla quando e como usar suas funções**. Ele só resolve um problema: construir interfaces. O resto? Você escolhe as ferramentas (roteamento, state global, etc)."

**✔️ Características**:

- **Foco específico**: "React não liga se você usa Redux ou Context API, ele só renderiza componentes."
- **Flexibilidade**: "Você monta o projeto do zero, como um LEGO!"

🎥 **(Exemplo visual)**:

- Código React com imports de hooks e componente simples.
- **Texto na tela**: "Biblioteca = Você no comando!"

---

### 🏗️ **O que é um Framework? (Next.js como exemplo)**

"Já um framework, como o Next.js, **dita as regras do jogo**. Ele te entrega uma estrutura pronta: rotas, SSR, API Routes… E você **precisa seguir o fluxo dele**, não o contrário!"

**✔️ Características**:

- **Tudo incluso**: "Next.js decide como rotas, renderização e até o backend funcionam."
- **Convenções claras**: "Pasta `pages`? Arquivo `_app.js`? É o framework mandando!"

🎥 **(Comparação direta)**:

- Tela dividida: React (pastas personalizadas) vs Next.js (pastas padronizadas como `/pages`).
- **Texto na tela**: "Framework = Estrutura pré-definida!"  

---

### 🔄 **Diferença Chave (Filosofia vs Prática)**

"Enquanto uma biblioteca é **ferramenta que você usa**, o framework é **um sistema que te usa**. É como comparar **comprar ingredientes soltos** (React) vs **receita com passo a passo** (Next.js)."

## 🎭 **Ato 3 – Conclusão (Quando escolher cada um?)**

🤔 **"E qual é melhor?"**  
"Depende do seu projeto!

✅ **Biblioteca (React, Vue)**:

- **Projetos menores** ou com necessidades únicas.
- Você quer **liberdade total** para inovar ou testar stacks.

✅ **Framework (Next.js, Angular)**:

- **Projetos escaláveis** que precisam de padrões.
- Equipe grande ou prazo curto? **O framework acelera tudo!**"
