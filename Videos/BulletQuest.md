## 🎭 **ATO 1 - APRESENTAÇÃO (0-1min)**

_Estabelecendo o mundo, personagem e problema_

### **GANCHO E CONTEXTO (0-20s)**

_Visual: Você mostrando agenda/bullet journal físico bagunçado_

"Opa, pessoal! Olha só essa situação: todo mundo que eu conheço vive reclamando que não consegue se organizar. Bullet Journal ajuda, apps existem aos montes, mas sabe o que falta? **Motivação real** para manter a consistência.

E foi aí que eu pensei: e se a gente gamificasse isso de verdade?"

### **APRESENTAÇÃO DO PROTAGONISTA E DESAFIO (20s-1min)**

_Visual: Você apresentando a si mesmo, depois a equipe_

"Eu sou gerente de projetos e tech lead, trabalho com metodologias ágeis no dia a dia. E decidi criar um projeto que vai além de mais um app de organização.

Montei uma equipe incrível:

- **Talisson**: designer e front-end
- **Jacob**: front-end focado em UX
- **Damião**: back-end
- E eu cuidando de testes, DevOps e gestão

O desafio? Criar algo que realmente **vicie** as pessoas a serem organizadas. Mas como fazer isso sem cair no clichê?"

## ⚔️ **ATO 2 - CONFRONTO (1min-2min15s)**

_Desenvolvendo o conflito e mostrando os obstáculos_

### **O PROBLEMA REAL (1min-1min20s)**

_Visual: Comparações entre apps existentes, desenhos no papel_

"Aqui está o confronto: todo app de produtividade falha no mesmo ponto - **falta de engajamento a longo prazo**.

_[Desenhando no papel]_ Duolingo funciona porque criou **competição social**. Bullet Journal funciona porque é **pessoal e flexível**. Mas ninguém ainda juntou essas duas forças de forma eficiente.

Nosso desafio técnico? Criar um sistema de ranking que seja justo, salas colaborativas que motivem, e um sistema de pontuação que não seja 'gamificação fake'."

### **ENFRENTANDO OS OBSTÁCULOS (1min20s-2min15s)**

_Visual: Código no terminal, testes rodando, GitHub Actions_

"E aí começaram os problemas reais de desenvolvimento...

_[Mostra terminal com testes]_ Primeiro obstáculo: como garantir que o sistema seja confiável? Implementamos **testes automatizados** desde o início. Olha só eles rodando - cada linha de código é testada.

_[Mostra GitHub Actions/Pipeline]_ Segundo obstáculo: como manter qualidade com uma equipe distribuída? **CI/CD completo**! Toda vez que alguém sobe código, os testes rodam automaticamente. Se quebra, todo mundo sabe na hora.

_[Desenha arquitetura no papel]_ Terceiro obstáculo: como estruturar para escalar? Arquitetura pensada desde o início. Backend sólido, API bem definida. Ainda não temos interface, mas a **fundação está sólida**.

E olha o mais desafiador: fazer isso tudo **open source**, transparente, criando oportunidade real para os integrantes terem experiência prática do mercado de trabalho e um projeto sólido para o portfólio."

---

## 🏆 **ATO 3 - RESOLUÇÃO (2min15s-3min)**

_Mostrando a resolução e o que vem pela frente_

### **A SOLUÇÃO EMERGINDO (2min15s-2min45s)**

_Visual: Estrutura do projeto, roadmap no papel_

"E aqui está nossa resolução: não estamos apenas criando mais um app. Estamos criando um **laboratório real de desenvolvimento** onde os integrantes da equipe vivenciam na prática como funciona o mercado de trabalho!

_[Mostra estrutura atual]_ Já temos: ✅ Sistema de usuários funcionando ✅ Testes automatizados rodando  
✅ Pipeline de CI/CD implementado ✅ Arquitetura escalável definida ✅ Metodologia ágil em prática

O projeto virou uma ponte entre teoria e prática. Cada integrante da equipe está construindo **exatamente** o tipo de experiência e portfólio que o mercado procura."

### **CALL TO ACTION E ABERTURA (2min45s-3min)**

_Visual: Você olhando diretamente para a câmera_

"E aqui vem o convite mais importante:

**Se você quer ter experiência real em desenvolvimento, mas não tem um projeto para mostrar no portfólio - me chama na DM! Podemos desenvolver um projeto juntos.**

Não importa se você é iniciante ou já tem alguma experiência. O que importa é vontade de aprender fazendo.

Nos comentários, me digam:

- **ARQUITETURA**: querem ver como estruturamos o backend?
- **TESTES**: interessados no processo de testes automatizados?
- **PRÓXIMOS PASSOS**: ansiosos para ver design e front-end chegando?

Curtam se gostaram da proposta, compartilhem com quem precisa de experiência prática, e se inscrevam para acompanhar toda essa jornada!

**Lembrem-se: experiência real só se consegue fazendo projetos reais. Quem topa entrar nessa comigo?**"
